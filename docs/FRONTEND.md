## 1. Что мы делаем

**HackAlem AI, трек 11 (спец-трек Казактелеком): ИИ-агент «Анализ организационной структуры и функционала».**

Пользователь — сотрудник, который анализирует реорганизацию. Он загружает комплект документов **«до»** и **«после»** (положения о подразделениях, оргструктуры, приказы; Word/PDF/Excel). Агент:

1. определяет, какие подразделения **созданы / сохранены / упразднены / переименованы**;
2. сопоставляет функции «до» и «после» и находит **потерю функций**;
3. находит **дублирование функций** и **потенциальный конфликт интересов**;
4. для **каждого** вывода показывает источник: документ + номер пункта + дословная цитата;
5. формирует итоговое **аналитическое заключение**.

**Как проверяет жюри (п. 11 ТЗ):** на контрольном комплекте с заранее известными изменениями (реорганизация, потеря функции, дублирование) смотрят: нашёл ли агент и **правильный ли источник**. Интерфейс должен делать это проверяемым за секунды: клик по находке → видно пункт и цитату «до/после».

**Ограничение ТЗ №9:** выводы носят рекомендательный характер; вывод без подтверждения в документах **не показывается**. В UI формулировки — гипотезы («признаки дублирования», «возможная потеря»), у каждой находки есть уверенность и кнопки «подтвердить / отклонить».

Критерии (100): соответствие и работоспособность 25 · техническая реализация 25 · **README и воспроизводимость 25** · ценность 15 · потенциал/оригинальность 10. Если проект не запускается по README — команда выбывает.

## 4. Контракт (предложение — сверить с A в 14:00–14:15)

Имена из `TASKS.md`, расширено до того, что нужно экранам. Если A уже положил свой `types.ts` — использовать его, а мок подогнать.

```ts
export type Side = 'before' | 'after';

export interface Clause {           // пункт документа
  id: string;                       // номер как в документе: '5.5.11', '3.4.б'
  side: Side;
  docName: string;                  // 'Положение о ВА, ред. 8'
  section?: string;                 // '5. Права и обязанности'
  text: string;
}

export interface Evidence {
  side: Side;
  docName: string;
  clauseId: string;
  quote: string;                    // дословная, проверена верификатором
  verified: boolean;
}

export type UnitStatus = 'created' | 'retained' | 'removed' | 'renamed';

export interface UnitChange {
  id: string;
  name: string;
  abbr?: string;
  kind: 'department' | 'position' | 'block';
  status: UnitStatus;
  parentId?: string;                // для схемы React Flow (подчинённость)
  side: Side | 'both';
  evidence: Evidence[];
}

export interface UnitFunction {
  id: string;
  text: string;
  unit: string;                     // abbr или id подразделения
  side: Side;
  clauseId: string;
}

export type MatchStatus = 'same' | 'changed' | 'moved' | 'lost' | 'new';

export interface FunctionMatch {    // строка таблицы сопоставления
  before?: UnitFunction;
  after?: UnitFunction;
  status: MatchStatus;
  similarity: number;               // 0..1
  note?: string;
}

export type FindingKind =
  | 'unit_created' | 'unit_removed' | 'reorganized'
  | 'function_lost' | 'function_duplicated'
  | 'responsibility_overlap' | 'conflict_of_interest';

export interface Finding {
  id: string;
  kind: FindingKind;
  severity: 'high' | 'medium' | 'low';
  title: string;                    // гипотеза: 'Признаки дублирования: контроль устранения недостатков'
  detail: string;
  units: string[];
  evidence: Evidence[];             // НЕ пустой, иначе не показываем
  confidence: number;               // 0..1
  recommendation?: string;
}

export interface AnalysisResult {
  meta: { beforeDocs: string[]; afterDocs: string[]; analyzedAt: string; model?: string; durationMs?: number };
  units: UnitChange[];
  functions: FunctionMatch[];
  findings: Finding[];
  conclusion: string;               // markdown
  stats: { created: number; retained: number; removed: number; lost: number; duplicated: number; conflicts: number };
}
```

Черновик мока на реальных пунктах: `docs/orgdiff-mock.draft.json` → после согласования переложить в `src/features/orgdiff/mock.json`.

## 6. Принципы UI

- Главное — **проверяемость**: от любой находки до цитаты не больше одного клика.
- Никаких утверждений без источника; находки с пустым `evidence` не рендерить (и логировать в консоль).
- Всегда два номера пункта (до → после), потому что нумерация сдвигается.
- Язык интерфейса — русский, термины как в документах (БВА, ДККМ, СВК).
- Демо идёт 5 минут: сценарий «тестовый комплект → анализ → сводка → находка → источник → заключение» должен проходить без единой ошибки.
- Стиль и конвенции — как в `CLAUDE.md` (React Query, nuqs, `PageContainer`, иконки только из `@/components/icons`, одинарные кавычки).
