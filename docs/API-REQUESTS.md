## P0 — без этого проседаем на проверке жюри

### 1. Находки `function_duplicated` на тестовом комплекте = 0

**Экран:** «Находки» — фильтр «Дублирование», карточка-счётчик «Дубли»; «Схема» — подсветка узлов.
**Проблема:** жюри проверяет дублирование функционала, а на тестовом комплекте вся категория пустая. Эталон `data/control/GOLD.md` сам содержит G21 и G27 (`duplication`). G21 (анализ результатов непрерывного аудита: 5.3.8 ↔ 5.4.5) пайплайн нашёл, но пометил как `responsibility_overlap` (F24). G27 (контроль устранения недостатков: 5.3.7, 5.5.5, 5.1.4, 9.58) не найден совсем.
**Нужно:** G21 и G27 → `kind: 'function_duplicated'`, в `evidence` — пункты не меньше чем двух носителей.

### 2. Пары источников «до ↔ после» в находке

**Экран:** B4 «Панель источника» — цитата «до» и «после» рядом с подсветкой отличий; правило FRONTEND §6: «всегда два номера пункта (до → после)».
**Проблема:** `Finding.evidence` — плоский список. У F4 в нём 8 цитат вперемешку (`до 3.4.а, до 3.7, после 3.4.в, после 3.8, до 5.3.2, после 5.4.2…`). По порядку в массиве UI не может надёжно понять, какой пункт «после» соответствует какому пункту «до».
**Нужно:**

```ts
export interface EvidencePair {
  before?: Evidence;   // нет — пункт появился только в «после»
  after?: Evidence;    // нет — пункт исчез (потеря)
  note?: string;       // 'нумерация сдвинулась', 'объём сужен: убрано «ежеквартально»'
}
// Finding
pairs?: EvidencePair[];
```

`evidence` оставить как есть: на него завязан фильтр «без источника не показываем».

## P1 — нужно для экранов B3–B5

### 3. Связь находки со строками сопоставления функций

**Экран:** клик по находке «Признаки утраты функции» → строка в таблице «Функции» (B3) с пунктом «до» и отсутствующим «после».
**Проблема:** у `Finding` нет ссылки на `FunctionMatch`, а для потерь и сужений находка по сути и есть строка таблицы.
**Нужно:** `Finding.matchIds?: string[]` (`FunctionMatch.id`).

### 4. Какие именно функции прошли по ребру схемы

**Экран:** «Схема» — клик по ребру «Директор направления → ДИТААД, 17 ф.» → список этих 17 функций с номерами пунктов.
**Проблема:** «17 функций переданы» — это утверждение, и ограничение 9 требует для него источник. У рёбер `retained` сейчас `evidence: []`, у `transferred` — 4 примера из 17.
**Нужно:** `UnitFlow.matchIds?: string[]` — все строки сопоставления, которые дали это ребро (`functionCount === matchIds.length`).

### 5. План шагов пайплайна заранее

**Экран:** B1 «Ход анализа» — все шаги видны с самого начала и честно считается процент.
**Проблема:** `trace` содержит только уже начатые шаги. UI не знает, сколько их будет, поэтому 11 шагов сейчас зашиты в интерфейсе.
**Нужно (любой вариант):**
- `AnalysisJob.plan: { id: string; label: string }[]` сразу после `POST`;
- или `trace` заполнен всеми шагами со статусом `'pending'` (добавить `'pending'` в `TraceStep.status`).

### 6. Подчинённость для схемы

**Экран:** «Схема» — по FRONTEND §5 B2 «рёбра — подчинённость»: Главный аудитор → департаменты, упразднённая должность → кому подчинялась. Сейчас на схеме видно только движение функций.
**Нужно:** `UnitChange.parentId?: { before?: string; after?: string }` (`UnitChange.id` руководителя; нет — подчиняется Главному аудитору или блоку).

## P2 — улучшает понятность, если останется время

### 7. Человекочитаемое имя документа

**Экран:** чипы источников `ред.9 п. 5.3.7` (FRONTEND §5 B5), шапка заключения.
**Проблема:** `Evidence.docName` и `SourceDoc.name` — имена файлов (`after_polozhenie_red9.docx`).
**Нужно:** `SourceDoc.title?: string` («Положение о внутреннем аудите, ред. 9 от 23.12.2022») и `SourceDoc.short?: string` («ред. 9»), если их можно достать из текста документа.

### 8. Оговорка к находке

**Экран:** карточка находки — строка «требует проверки: …».
**Зачем:** GOLD п. 9 — коллективный субъект п. 5.3 («Директоры департаментов и Директоры направлений ДИТААД и ДОА») нужно показывать как неопределённость, а не как установленный факт.
**Нужно:** `Finding.caveat?: string`.
